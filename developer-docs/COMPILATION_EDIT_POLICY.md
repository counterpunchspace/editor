# Compilation Edit Policy

This document is the authoritative source for how edit sources map to compilation scheduling, compilation modes, worker caching, and canvas update behavior in the editor. Changes to this behavior are policy changes, not incidental refactors.

If you change compilation behavior, update this document in the same change and discuss the policy change with the author before merging it.

## Goals

- Use the fastest safe compilation mode for each edit type.
- Keep the incremental worker path hot: incremental layer patching, cached babelfont reuse, cached subset reuse, and the editing subset target before fontc.
- Preserve a trailing full compile after interactive edits whose committed packet still used a fast-path edit type, and stamp preview-backed outline/anchor/sidebearing commits as already-full (`editType: null`) so they do not reshape through an incomplete middle compile.
- Avoid accidental regressions where an optimized compile mode still exists in code but stops being scheduled.
- Full binary fonts are compiled only for explicit user export or isolated assistant analysis; no background full-font monitor runs after edits or on startup.

## Sparse Worker Shards

Sparse cloud core may retain only the opening subset in `glyphOrder`, while
later glyph shards are authoritative and resident in the worker Y.Doc.
`assembled_babelfont_json()` MUST preserve the declared glyph order and append
every known glyph-shard name deterministically before rebuilding Rust caches.
Otherwise a hydrated glyph can exist in the bridge and overview model but be
absent from worker outline requests. This is bootstrap/reconciliation behavior,
not a steady-state full-document JSON repair path.

## Graph Chokepoint Enforcement

CI refreshes the GitNexus graph and runs `npm run check:graph-chokepoints` before
the webapp build. The checked-in caller baselines in
`architecture/graph-chokepoints.json` protect the committed edit funnel, remote
Yjs ingress, authoritative worker Yjs forwarding, cached editing compilation,
full binary compilation, whole-worker Y.Doc seeding, and raw worker Yjs sends.
The same check parses full-document request objects, including literal-backed
`type` variables, and limits the live `seedYdoc` and `storeFontJson` messages
to reviewed bootstrap, rebaseline, and no-bridge source-reload owners. It also
allowlists production `toCompileJSON()` call sites (preview/export only) and
requires resting layer writebacks (`syncFromEditorLayerData`, Y.Doc layer
deltas, history snapshots, storage serialization, worker preflight) to call
`resting-layer-json.ts`. History buffering must run that codec (or
`_normalizeLayerSnapshot`) before recording a layer snapshot so missing
`width`/`master` and interpolator keys cannot enter undo/redo payloads. A production caller, full-document request, new
compile-facing call, or dropped codec call fails CI unless the implementation
is routed through the existing boundary or the exception is deliberately
reviewed and recorded in that baseline. This structural gate
complements behavioral tests: it prevents a newly introduced sidecar from
bypassing the policy before a scenario test has a chance to miss it.

## Core Rules

1. Active mouse drags must continue triggering live editing compiles.
2. Active mouse drags must not trigger full compiles or the full babelfont JSON sync that feeds those full compiles while the pointer is still down.
3. Full binary compilation is explicit-only and must not be scheduled by editing, startup, or synchronization paths.
4. Interactive keyboard edits must still compile live.
5. Interactive enriched edits must still schedule a trailing debounced full compile after the interaction settles.
6. Interactive edit-time flows must keep the Rust worker congruent via incremental Yjs updates only. Edit-time Rust promotion is incremental-Yjs-only; worker-cache JSON patch batches, full babelfont JSON resends, and full Yjs-state resends are not part of the steady-state editing path.
7. Editing compiles must continue using the subsetted `editing` target before fontc. `FontManager.recompileEditingFont()` MUST NOT trust a stale narrow `editingSubsetSnapshot` alone: it MUST widen that snapshot by merging glyphs derived from the current text buffer and `getLiveVisibleGlyphNames()` before compiling, so visible dependents (for example `adieresis` while editing `a` in an `aä` run) stay inside `SUBSET_JSON_CACHE` and remain patchable via `workerReplayTargets`. The initial startup compile runs before URL/state restore applies `?text=` and `?features=` to the live buffer, so `compileEditingFont()` / `recompileEditingFont()` MUST derive that first subset from the URL `text` parameter (or restored `editor_text_buffer`) rather than the constructor default `Hamburgevons`, and MUST use the URL `features` parameter (or restored `editor_opentype_features_in_subset`) as `selectedFeatures` whenever `isStartupStateReady()` is still false. Extra compiles during `font.openSession` may skip only when they repeat the same subset key already compiled in that session; a later request that widens the subset (URL restore of `Hämburger` after a default `Hamburgevons` compile) MUST still compile so mapped glyphs are not left as `.notdef`.
8. Text input uses its own subset-only fast path and still schedules a deferred full compile after typing settles.
8a. Cloud sparse compile hydration is forward-only: seeds, layout closure, and explicitly visible dependents, then component/metrics-key prerequisites. UI overview hydration may still reverse-close composites. `compileEditingFont` keeps at most one in-flight WASM compile and one latest-wins trailing request.
9. Full compiles remain the correctness fallback after interactive editing or when an edit type does not have a specialized fast path.
10. Linked windows must not schedule background full binary compilation. Explicit export and assistant analysis seed their isolated worker from settled committed state.
11. Every interactive commit MUST keep the JS and Rust documents aligned through the shared Yjs transaction stream. Full-font `storeFontJson`, `seedYdoc`, `initYdoc`, or any other full-document crossing MUST stay at zero during steady-state editing, undo, redo, Python execution, feature-code commits, and linked-window edit replay. Edit-time compiles must wait for the already-emitted incremental Yjs worker update instead of forcing any full-document resend. Layer-scoped outline, anchor, sidebearing, component, guide, and visual layer packets MUST carry `layerTargets` to Rust so `apply_yjs_update` can patch canonical and subset caches from the same sparse Yjs delta without a second direct layer update or whole-glyph cache serialization.
12. Every committed Yjs packet, local or remote, MUST enter one shared serialized committed-change funnel for post-commit reactions. That funnel owns committed edit-type inference, editing-compile wakeup, and overview invalidation. Sender-local save helpers may prepare model state and arm trailing debounces, but they MUST NOT run a separate committed compile or committed `glyphChanged` path in parallel.
13. Missing replay metadata, worker-sync rejection, or any other edit-time inconsistency MUST be treated as a bug in the incremental pipeline, not as justification for a full-document repair path. A rejected steady-state worker packet MUST quarantine the worker document (discard the Rust worker Y.Doc and caches) and MUST NOT resend that rejected packet. When `PatchSyncEngine.encodeBridgeState()` is available, `sendWorkerYjsUpdate` MUST immediately re-seed Rust from that bridge state (the same permitted bootstrap/rebaseline as cloud reconnect) so compile is not left dead until the next edit. If reseed is impossible, keep the worker-ready gate closed and block later incremental updates until an explicit `encodeBridgeState()` bootstrap completes. Main-thread code MUST NOT keep a second long-lived JS `Y.Doc` as a worker mirror or whole-layer encode base. JS MUST refuse `applyYjsUpdate` when a targeted Y.Doc layer is not resting JSON (`resting-layer-json.ts`). Incremental `applyYjsUpdate` worker payloads MUST structured-clone the Yjs delta; they MUST NOT transfer the encoder `ArrayBuffer`, because detaching a reused Yrs/Yjs buffer drops later packets and leaves the worker Y.Doc behind the bridge. Bootstrap `seedYdoc` MAY transfer a uniquely owned state buffer. A successful incremental worker acknowledgement MUST mean every **packet-affected** layer or glyph snapshot can be strictly deserialized into the native cache model before canonical, subset, or native cache mutation; `apply_yjs_update` MUST NOT clone or deserialize the entire active subset from Y.Doc on each visual commit. A temporarily usable native cache is not proof of cache coherence. Normal editing has no escape hatches.
14. Collaboration and cloud convergence MUST use binary Yjs updates as the authoritative document transport. Semantic change metadata may accompany those updates for history, human-readable inspection, undo labels and scopes, and replay-target hints, but it MUST NOT be used as the state-replay source for normal linked-window or cloud convergence. A non-noop steady-state remote/cloud Yjs update without semantic metadata is a protocol violation and MUST be refused before mutating the live bridge, because the receiver cannot legally perform scoped JS-model refresh, replay-target handling, or compile-context inference without that metadata. The cloud transport MUST close terminally on such a violation and MUST NOT request a state-vector reconciliation as repair. True CRDT no-op reconciliation packets may be suppressed before worker/compile side effects.
    **External source reload after bridge initialization is a committed Yjs edit.** Reading/parsing the source may cross the full-font boundary once, but `FontManager.reloadCurrentFontFromSource` MUST capture the bridge state vector before that asynchronous read and submit the parsed snapshot through `PatchSyncEngine.applyExternalSourceReload`. The bridge must reject the snapshot if that vector is stale, preserve existing glyph and layer Y.Map identities while applying it, and emit exactly one ordinary committed Yjs packet plus one atomic history item composed of minimal structural operations, never a whole-font history snapshot. That same packet is the only worker, linked-window, cloud, undo, and compile transport. The active-bridge path MUST NOT call `storeFontJson`, `seedYdoc`, `initYdoc`, or allocate a second JS worker-mirror `Y.Doc` after parsing. Full-document worker initialization remains permitted only when no bridge exists yet.
15. Python edits MUST enter `PatchSyncEngine` and emit the same committed Yjs packet plus change-log metadata as every other persisted edit. Python may derive synthetic operations from normalized before/after font snapshots, including named path metadata, but it MUST first canonicalize the current font in place and refresh the serialized snapshot, then derive the post-execution snapshot from that freshly regenerated canonical serialization rather than from any stale pre-sync `babelfontJson` cache. It MUST NOT bypass the shared committed-change funnel with ad hoc full-font sync or direct post-commit reactions.
    Assistant prompts group history through stable metadata, not by keeping a physical `PatchSyncEngine` transaction open. Each prompt-derived Python or direct font edit MUST open and close its own bounded transaction immediately, emit its authoritative incremental Yjs packet, and enter the committed-change funnel so the editing worker, editing-font compile, and visible shaping state update before the prompt continues. Every such transaction MUST carry the prompt ID as both `historyItemId` and `promptGroupId`; this makes the history and undo reducers expose all prompt edits as one logical item and one undo step without delaying normal collaboration or compilation. The history item uses the `set_prompt_history_summary` text when supplied, otherwise `Assistant changes`. Stop MUST NOT create a synthetic final bridge transaction. Python snapshot diffs MUST preserve ordered collection fidelity through the Y.Doc schema: keyed glyph and layer maps use their dedicated order arrays, while ordinary JSON arrays use schema-compatible atomic replacements. This prompt grouping MUST NOT use `storeFontJson`, `seedYdoc`, `initYdoc`, or any full-document repair traffic.
16. Visual glyph edits MUST NOT invalidate the layout-closure cache. The closure may be re-primed only when the closed glyph set changes, which is driven by the editing text/subset or the selected OpenType feature set, or when feature/glyphset source data changes. Outline, anchor, sidebearing, component transforms, guide, and layer-visual commits must keep the existing closure intact. Component-reference add, replace, and delete commits are the narrow exception: they change the transitive component-source closure, so their ordinary incremental Yjs packet MUST set `invalidateLayoutClosure: true`; the worker then re-primes the existing closure from the unchanged text roots. The same flag MUST also be forwarded into Rust `apply_yjs_update` metadata so Rust drops `SUBSET_JSON_CACHE` / `SUBSET_FONT_CACHE` instead of in-place patching a subset that may briefly reference glyphs outside the previously closed set; the next primed compile rebuilds the subset from the full font. No JavaScript-side component source expansion or full-document transport is permitted.
17. Startup bridge/bootstrap noise MUST NOT request a no-data committed editing compile before the first editing font exists. The initial startup editing compile owns first readiness; bootstrap-local packets with `changeVersion === 0` must not bump `compileRequestVersion` and invalidate that first result. That first compile MUST include every glyph implied by the load URL's `text` (via `Font.findGlyphByCodepoint` / `deriveSubsetGlyphsFromText`), not only the default or localStorage text buffer, and MUST pass the load URL's `features` as `selectedFeatures` so layout closure matches the restored OpenType feature set. The open-session one-compile gate exists to avoid redundant full compiles, not to freeze a too-narrow subset.
18. **Bridge-finalizer bypass for GUI-complete layer packets.** `buildCascadingRecompositionOperations` MUST skip cascade recomposition when every cascade-triggering operation in the transaction already carries complete `workerReplayTargets` that include the source glyph/layer pair **and** the transaction includes layer-snapshot writes whenever multi-target replay metadata claims a cascade (`operationsIncludeSnapshotsForClaimedCascade`). The predicate `operationCarriesCompleteGuiReplayTargets` detects source completeness: a cascade-triggering operation (width, anchor, layer-snapshot, glyph-snapshot with cascade data) is complete when it has non-empty `workerReplayTargets` and at least one target matches the operation's own `(glyphName, layerId)`. When all cascade-triggering ops are complete **and** claimed cascade snapshots are present, the finalizer returns `[]` without calling `recomputeCascadeAffectedGlyphNames`. Producers that supply complete recomposed snapshots include the anchor, sidebearing, and outline drag-end paths in `outline-editor.ts`; those producers MUST run the shared `computeLayerRecompositionClosure` once (live: `scope:'visible'`; commit: `scope:'all'`) and then serialize-only sync — they MUST NOT rebuild automatic composites again inside `_syncCurrentGlyphToYDoc`. These producers MUST pass explicit changed-layer snapshots into `PatchSyncEngine.syncLayerSnapshotsFromJson` when recomposed dependent layers were updated outside the directly edited storage branch, so Yjs diffs are computed against the current Y.Doc state rather than against any aliased whole-font JSON object. They MUST also refresh the matching local stored layer JSON for each explicit snapshot so post-commit redraw and fetch paths cannot resurrect stale downstream automatic-composite data after the live preview overlay clears. Producers MUST use only `source ∪ recomposeTargets` as `changedLayerTargets` while stamping the wider `allTargets` (source ∪ recompose ∪ invalidate) as `workerReplayTargets`, each with matched per-glyph layer ids. When the finalizer does run, it MUST infer edit kinds from the buffered operations and MUST write cascade layer snapshots only for `recomposeTargets`, never for invalidate-only component dependents (manual composites keep stored width/translates). Commit-time `recomposeTargets` MUST still include automatic-aligned component dependents (and metrics-key dependents) after sidebearing/outline/component edits even when the final rebuild/metrics pass is a no-op (**persistence gate**), so live-already-updated dependents are persisted into Yjs. `PatchSyncEngine.syncLayerSnapshotsFromJson` MUST reload object-model layers only from layers actually written into that packet, never from the wider invalidate-only `workerReplayTargets` set. Incomplete packets (e.g. plain width/anchor scalar paths without explicit replay targets, or multi-target replay without layer snapshots) still fall back to the finalizer recomposition. Automatic `=+/-=` resting state in model and Yjs is logical (`Layer.toJSON`); bake only via `Layer.toCompileJSON` at compile/export/preview. See `webapp/js/change-bridge-init.ts` `operationCarriesCompleteGuiReplayTargets`, `operationsIncludeSnapshotsForClaimedCascade`, and `buildCascadingRecompositionOperations`, and `webapp/js/recomposition-closure.ts`.
    Rule 18 clarification: a claimed cascade is complete when the packet includes an actual layer-scoped write for at least one claimed downstream replay target. That write may be granular or a layer snapshot. A source-only write with broad replay metadata is not proof that dependents were persisted and MUST still enter fallback recomposition.
18b. **Undo/redo of cascade-capable packets re-settle derived layers.** Forward commits still persist origin plus cascade snapshots in one Yjs packet. Undo and redo of that item MUST restore only originating-glyph writes, then run `computeLayerRecompositionClosure` (`scope: 'all'`) against the current font model and write `recomposeTargets` into the **same** undo/redo Yjs transaction. Automatic composites and metrics-key inheritors follow the restored origin. Dependents that are no longer automatic MUST NOT be rewritten from stored cascade snapshots. This is not a second undo funnel: remotes apply that one Yjs update. Headless paths without a font model MAY fall back to snapshot replay of derived entries. See `PatchSyncEngine._applyHistoryItem` and `shouldResettleDerivedLayersOnHistoryReplay`.
19. **Committed replay targets are metadata only; the worker mutates exactly once per authoritative Yjs packet.** After `awaitCommittedWorkerCacheSettled` resolves, the authoritative binary Yjs update has reached Rust through `forwardWorkerYjsUpdate`. That forwarded bridge packet is the only steady-state worker-document mutation allowed for local commits, remote replay, undo, and redo. `workerReplayTargets` and `layerTargets` remain required metadata for compile-context inference, drift inspection, overview invalidation, and Rust-side targeted cache patching, but `handleCommittedChangeRefresh` MUST NOT schedule a second worker-document mutation (including whole-layer reserialization or any JS-side mirror encode) before compile.

The committed funnel therefore waits only for the already-forwarded authoritative worker update plus any pre-existing worker-cache promise chain tracked by `awaitCommittedWorkerCacheSettled`. Sender-local, receiver-local, undo, and redo paths MUST compile from that same authoritative worker Yjs state.

The rule preserves the no-full-document constraint: steady-state local edits, undo, redo, linked-window replay, cloud replay, Python execution, and feature-code commits still MUST NOT use `storeFontJson`, `seedYdoc`, `initYdoc`, full Yjs-state resend, full babelfont JSON repair, or whole-layer worker-cache rewrite as an edit-time correctness path.

**Single long-lived JS `Y.Doc`.** `PatchSyncEngine.yDoc` is the only retained main-thread Yjs document. The compilation worker owns the Rust `Y.Doc`. Main-thread code MUST NOT allocate a second long-lived `Y.Doc` to mirror Rust, encode whole-layer deltas, or repair worker drift. Bootstrap and quarantine recovery reseed Rust only from `encodeBridgeState()`.

See `webapp/js/change-bridge-init.ts` `handleCommittedChangeRefresh`, `webapp/js/font-manager.ts` `forwardWorkerYjsUpdateInternal`, and `awaitCommittedWorkerCacheSettled`.

20. **Tighter layout-closure invalidation for visual paths only.** `shouldInvalidateLayoutClosureForCommittedEntries` MUST return `false` for paths that contain `.layers.` or `:layers.` — these are visual layer-scoped edits that only change data inside the existing closed glyph set. Dependent `workerReplayTargets` on outline, anchor, sidebearing, component, guide, or layer-visual packets remain metadata for Rust cache refresh and compile scoping; they MUST NOT invalidate or re-prime layout closure. It MUST also return `false` for the forwarded master-reinterpolation batch packet labeled `Reinterpolate layer batch sync` when that packet carries explicit layer `workerReplayTargets`, even though the apply path is a glyph snapshot; that packet only rewrites layer contents inside the existing closed glyph set. Glyph-level metrics-key metadata (`glyphs.<name>.format_specific.metric_left` / `metric_right` and the Glyphs `metricLeft` / `metricRight` aliases) MUST also return `false`: those formulas do not change the closed glyph set, and clearing `SUBSET_JSON_CACHE` for them races later editing compiles that still need the active subset. The function still returns `true` for `features.*` paths and other `glyphs.*` paths without layer scope (structural changes such as glyph add/remove/replace). See `webapp/js/change-bridge-init.ts` `shouldInvalidateLayoutClosureForCommittedEntries`.
21. **Worker-side sentinel clearing respects explicit `invalidateLayoutClosure: false`.** The `applyYjsUpdate` handler in `fontc-worker.ts` MUST NOT clear `cachedBaseSubsetKey` / `cachedClosureGlyphCount` when the sender passes `invalidateLayoutClosure: false`, even if `changedGlyphCount === 0`. The old condition `changedGlyphCount === 0` that overrode an explicit `false` was removed. Feature-code and top-level updates still invalidate closure by sending `invalidateLayoutClosure: true`. See `webapp/js/fontc-worker.ts` `applyYjsUpdate` handler.
    Rust must keep the filtered editing font current after successful layer/glyph Yjs updates that touch the active subset. That is separate from layout-closure invalidation: visual commits keep the JS primed closure key intact. When `FILTERED_FONT_CACHE` matches the active subset key, Rust patches the cached filtered font in place (layer/glyph replace plus automatic sidebearing bake) so `compile_cached_font_from_last_layout_closure()` can reuse it without re-running the filter pipeline. Patch failure, feature-code, master, axis, rename, layout-closure invalidation, **or a canonical font that contains `fip001-boolean` subtraction paths**, still advances `FILTER_EPOCH` and clears `FILTERED_FONT_CACHE`. Boolean subtraction (`Fip001Boolean`) runs in the editing and IR filter pipelines after background-layer strip and before `DropIncompatiblePaths`; in-place cache patches cannot reconstruct that result from source snapshots, so those fonts always re-filter. Cloud reconnect rebaseline still reseeds and drops those caches. Layer/glyph updates outside the active subset should patch canonical state without forcing the current filtered editing subset to rebuild.
22. **Node arrays are the sole representation.** Persisted path shapes, `.babelfont` JSON, cloud snapshots, Y.Doc room state, worker bootstrap snapshots, Rust-facing JSON, and Rust JSON caches MUST use `Babelfont.Node[]`. In Y.Doc, `nodes` is a `Y.Array` of node maps. Node strings are invalid and MUST fail visibly at the boundary; no parser, serializer, migration shim, or compatibility fallback is permitted. Editor-only node/path/component ids MUST NOT be emitted in saved or Y.Doc path/component storage.
23. **Undo/redo control rows must never define emitted packet semantics.** Undo and redo may append coarse control entries to the change log only to rotate history-stack state (`targetHistoryItemId`, `Undo`/`Redo` labels, scopes). Those control rows MUST NOT be forwarded as the semantic metadata observed by local update listeners, worker callbacks, collaboration transport, or the committed-change funnel. For packets that do not re-settle derived layers, emitted committed packets MUST unwrap back to clones of the original forward entries from the same authoritative Yjs delta, with only `historyAction` changed to `undo` or `redo` and `targetHistoryItemId` attached. Cascade-capable undo/redo (rule 18b) emits the **origin restore plus freshly settled dependent writes** as that packet’s Yjs delta; remotes MUST treat that delta as truth and MUST NOT invert the original combined forward transact. Semantic compile metadata MAY still clone the original forward entries (with `historyAction` updated) so edit-type inference stays stable. Local emissions MUST pair each authoritative Yjs delta with the semantic entries for the committed packet being emitted; a global change-log cursor may not define packet semantics. Undo/redo-specific local emission helpers are forbidden.
24. **Worker document mutations close the compile-ready gate before posting.** `storeFontJson`, `seedYdoc`, and `applyYjsUpdate` mutate the Rust worker document/cache and may clear the primed layout closure. `FontCompilation.sendMessage()` MUST set `workerCacheDocumentReady = false` synchronously before posting any of those messages, then restore readiness only after the matching worker response succeeds. Failed document mutations, including failed `applyYjsUpdate`, MUST keep the tracked worker-document sync rejected and the ready gate closed; cached editing compiles may not treat a rejected worker update as a settled sync. Cached editing compiles MUST wait for the tracked worker-document sync whenever that gate is closed. Live-drag preview compiles MUST NOT be requested while the worker document is explicitly not ready; later drag refresh frames may request preview compiles after the worker gate reopens. This prevents linked-window bootstrap or any other worker reseed/update from racing a cached editing compile that would otherwise try to reuse a JS-visible subset key after Rust cleared its layout-closure cache.
25. **Top-level kerning edits use kerning-specific non-glyph hints without invalidating layout closure.** Commits under `masters.*.kerning`, `masters.*.kerning_rtl`, `format_specific["com.schriftgestalt.Glyphs.kerningRTL"]`, `first_kern_groups`, and `second_kern_groups` MUST forward `nonGlyphChangeHints` so Rust can patch only kerning/group data in the canonical and subset caches. RTL kerning commits update both the editor-facing `masters.*.kerning_rtl` field and the canonical `format_specific` source in one authoritative Yjs transaction; the Rust worker refreshes both cache representations before compiling. These commits MUST keep `invalidateLayoutClosure: false` because they do not change the closed glyph set; only feature-code edits or structural glyph-set edits may invalidate the closure.
    Other non-glyph root-field commits MUST forward `top-level:<key>` metadata, including bracketed paths such as `format_specific["..."]`. Rust patches only those named canonical/subset cache entries and rejects metadata-free non-glyph updates rather than traversing the full Y.Doc.
    When a packet also carries glyph/layer changes (the partial-update path), `top-level:axes` MUST still refresh axes in `CANONICAL_JSON_CACHE`, subset JSON, and `FONT_CACHE` (and clear the outline cache). Add-master axis-map extensions travel with per-glyph layer targets; dropping the axes patch leaves live interpolation on a stale avar map and past-endpoint PiecewiseLinearMap extrapolation produces frankenstein outlines between the previous last master and the new one.
    **Packets that mix a kerning-value or kerning-groups stamp with glyph or layer paths MUST compile as `full` (`editType: null`), never `kerning-only`.** The writer keeps the kerning stamp on the gesture. The committed funnel sees the derived glyph or layer writes in the same packet (automatic ligature rebuilds travel with the kerning paths) and selects one immediate full compile. It does not infer an edit type from paths. A kerning path whose packet is stamped `null` stays full. Pure kerning packets remain `kerning-only` because the writer stamps `kerning-value` or `kerning-groups` and the packet has no glyph or layer write. `kerning-only` sets `produce_varc_table: false` and still compiles outlines; `skip_outlines` is not set.
    **`apply_yjs_update` MUST refresh kerning caches on the partial layer/glyph path when `nonGlyphChangeHints` includes `kerning-groups` or `kerning-value`.** The dedicated non-glyph branch is skipped whenever `layerTargets` or `changedGlyphs` are present. Without this refresh, canonical/subset JSON and GPOS keep the pre-edit class membership even though the JS object model and Y.Doc already contain the new groups.
26. **The compilation worker is the only Rust/Yjs document owner.** Main-thread code MUST NOT maintain a second Rust/Yrs mirror for interpolation, batch generation, or cache repair. Operations that need Rust-authored document changes, including add-master interpolation, remove-master layer deletion, single-layer reinterpolation, and whole-master reinterpolation, MUST call the compilation worker and receive a Rust-generated incremental Yjs update. That update is the only state transport back into `PatchSyncEngine`; metadata returned with the worker response may describe history operations and replay targets, but it MUST NOT be treated as a parallel state sidechain or replacement for the binary Yjs diff. After add-master interpolation, the main thread MAY recompose **newly inserted automatic layers only** in memory and request a worker `refine_layer_snapshots_yjs` pass that folds those overrides into the same base-state `encode_diff` before a single `applyLocalGeneratedYjsUpdate`; it MUST NOT emit a second history/sync packet for that recomposition.
    **Add-master and remove-master commits MUST compile as `full`, never `outline-only`.** Even though those packets carry per-glyph layer `workerReplayTargets`, they change master topology (`fvar` / `avar` / `gvar`). Classifying them as `outline` leaves the editing VF without the added or removed master tuple, so userspace locations past the previous extrema fall back to the default master. The writer stamps `editType: null` (`master-topology` or full) for `Add master` and `Remove master`, which selects the full editing compile path for both local and remote packets. A committed local reinterpolation packet also compiles `full`. `outline-only` and `anchor-only` require `dataFreshnessMode: 'live-drag-worker-preview'` or a `remote-*` change source.
    **Out-of-range add-master locations MUST extend axes in the same packet.** Before interpolating layers, `Font.addMaster` extends any axis whose designspace coverage does not include the new master location: without a map it widens userspace/designspace `min`/`max`; with a map it appends an extrapolated userspace↔designspace endpoint and widens `min`/`max`. Those axis writes travel in the same Rust-authored Yjs update (and history operations) as the new master and layers so undo, sliders, and the trailing full compile all see one coherent topology.
    **Oversized add/remove-master `layerTargets` MUST NOT quarantine the worker.** `buildApplyYjsUpdateMetadataJson` soft-caps sparse `layerTargets` (512). When a structural flood exceeds that cap, metadata MUST fall back to whole-glyph `changedGlyphs` (unique names from the targets), empty `layerTargets`, and ensure `masters` + `top-level:axes` hints so Rust applies the Yjs delta and refreshes glyph/master/axis caches without throwing. Throwing at the cap quarantines the worker document and leaves live outline interpolation on the pre-add topology. If the worker is quarantined after a rejected or skipped `applyYjsUpdate`, `sendWorkerYjsUpdate` MUST re-seed once from authoritative bridge state (same recovery class as cloud reconnect) on that failed send, then again before accepting a later incremental update if quarantine remains.
27. **Editing compile context is request-scoped and packet-explicit.** `lastChangeSource` / `lastEditType` are transient scheduling inputs only; committed local, remote, undo, and redo compiles MUST derive `{ changeSource, editType, dataFreshnessMode }` from the currently processed committed packet and pass that context explicitly when incrementing `compileRequestVersion`. `compileEditingFont()` MUST read the snapshot for the exact request it sends to Rust and MUST NOT fall back to ambient `lastChangeSource` / `lastEditType` when that request has no snapshot. Live drag refreshes may set the global context only long enough to request their compile, and SHOULD also pass the same explicit context into the request, then MUST clear the global state again so a late live request cannot poison the next committed, keyboard, undo, or redo compile. Interactive `saveLayerData()` may increment `compileRequestVersion` to invalidate stale in-flight live compiles, but it MUST NOT set `needsRecompile` or global compile context before the authoritative Yjs commit reaches the shared committed-change funnel. `pendingBabelfontJsonSyncAfterDrag` tracks only whether the local canonical babelfont JSON string still needs rebuilding for later full-JSON consumers; it MUST NOT override a request-scoped `dataFreshnessMode: 'authoritative-worker-yjs'` proof that the committed worker Yjs update has already settled for that exact compile request. Live drag requests may similarly mark `dataFreshnessMode: 'live-drag-worker-preview'` after the worker has accepted a sparse preview layer overlay. Those explicit freshness proofs apply only to cached worker-backed editing compiles: once `workerCacheDocumentReady` is true, `compileEditingFromJsonCached()` sends only the incremental sentinel and compiles either from the authoritative worker Y.Doc or, for `live-drag-worker-preview`, from the authoritative cached subset plus that sparse preview layer overlay. Canonical JSON resync and validation are intentionally bypassed for those proven-fresh cached requests. The initial startup editing compile (`startupOpenSessionActive`) likewise MUST NOT resync or validate the local babelfont JSON string when the worker document is already ready or an in-flight `seedYdoc` from this open is tracked: that compile waits on `awaitWorkerDocumentSync()` and consumes the worker Y.Doc, not main-thread JSON. Undo/redo/remote/`pendingBabelfontJsonSyncAfterDrag` and any path that still consumes local JSON still MUST resync and validate. Requests without one of those explicit freshness proofs, and feature-code which still compiles from canonical JSON, still MUST resync canonical JSON before compiling when `pendingBabelfontJsonSyncAfterDrag` is set.

28. **Cloud reconnect bootstrap reseeds Rust from the bridge before connected status.** A cloud `sync-response` after first connect or reconnect is bootstrap/rebaseline traffic, not steady-state editing. After applying the server's binary Yjs state to `PatchSyncEngine`, `CloudAdapter` MUST reseed the editing Rust worker from the current bridge binary Yjs state (`seedYdoc`) and call `FontManager.acknowledgeWorkerBridgeReseed()` (or the shared recover path that does the same) before it reports `connected` or runs the visible reconnect compile. That acknowledgement clears `workerMirrorQuarantined`, resets worker layer fingerprints, and opens the worker-ready gate so later incremental packets are not forced through a redundant recover. An R2 HTTP checkpoint apply MUST likewise reseed the editing worker from the bridge when `fontCompilation` is already initialized, and MUST track that seed on the same worker-bridge sync promise so compiles wait for alignment before the later WebSocket sync-response. No second JS worker-mirror `Y.Doc` may be allocated. This exception does not relax the steady-state rule: live edits, committed edits, undo, redo, Python execution, and remote replay still MUST NOT use full-document repair.
29. **Linked-window bootstrap tracks the worker-document sync before the first compile.** A linked window (`linked=1`) intentionally skips the initial worker `seedYdoc` at bridge-init time (rule: `!windowRole.isLinkedWindow()`). Instead, it requests the full Yjs state from the main window via `WindowSync.requestFullState()` and bootstraps the worker when the `full-state-response` arrives. Because the main-window response arrives asynchronously via BroadcastChannel, `requestFullState()` MUST pre-register a pending worker-document sync promise with `FontCompilation.trackWorkerDocumentSync()` **before** sending the request. This ensures `awaitWorkerDocumentSync()` in `compileEditingFromJsonCached()` blocks until the linked-window `seedYdoc` completes, preventing the initial editing compile (and any text-input compiles) from racing the bootstrap and failing with "requires a ready worker Yjs document". Live-drag preview wakeups also MUST respect this gate and skip compile requests until the worker document is ready. The bootstrap promise MUST be resolved when `seedYdoc` succeeds, rejected when it fails, and have a safety timeout (15s) so compiles don't hang forever if no peer responds. This is the same principle as rule 24 ("cached editing compiles MUST wait for the tracked worker-document sync whenever the gate is closed") applied to the linked-window bootstrap path.
30. **Assistant shaping observes only settled committed worker state.** `compile_and_shape_font` MUST wait for both the editing worker-document sync and the current `FontManager.workerCacheUpdatePromise` before capturing its font revision or compiling. It MUST fail when the editing worker cache is not ready or an update rejects. On a cache miss it MUST take a binary Yjs snapshot of that settled bridge state and seed only the separate `fullFontCompilation` analysis worker before compiling the full font and its debug subset. The editing `fontCompilation` worker MUST receive no compile, seed, cache-reset, or other mutation from this tool. This isolated analysis seed is permitted because it cannot repair or perturb steady-state editing; it must preserve every schema field in the committed bridge state and fail visibly if that state cannot be seeded. During active drag or keyboard preview state, as reported by `OutlineEditor.hasPendingKeyboardPreviewCommit()`, the tool MUST refuse both before and after its worker-state wait rather than silently compiling the older committed font, because its debug subset lane has no preview-overlay equivalent.
31. **Prompt tools observe their own settled packet.** An assistant mutating tool MUST await the exact shared committed-change-funnel promise enqueued by its own bounded transaction before returning. Assistant Python execution, including shared Pyodide stdout setup and cleanup, MUST be serialized. If Python throws after committing mutations, the tool MUST wait for that same packet and report an explicit partial-commit outcome; it MUST NOT imply a rollback. Prompt interruption MUST NOT mutate an already-emitted history row or create a synthetic transaction.
32. **Unknown stamps fail closed, and a commit compile waits for its own worker patch.** `assertCompileStamp` throws when `compileEditType` is not a known stamp or explicit `null`. A packet that already carries an unknown string logs and compiles `full`; it is not treated as a writer-chosen `null`. History and kerning-pair view locks read `compileEditType` only. A kerning path with no kerning stamp is not a kerning edit. `awaitCommittedEditingCompileReady` waits for this packet’s `forwardWorkerYjsUpdate` even when a worker document already exists. Outline, anchor, and sidebearing fast paths are live preview or legacy remote only; a committed local packet with one of those stamps compiles `full` and does not arm a deferred full compile.

### Exact Model Canvas Refresh

After the authoritative worker Yjs update has settled, committed local visual
edits SHOULD prefer `OutlineEditor.refreshSelectedLayerFromModel()` over
`OutlineEditor.fetchLayerData()` when
`OutlineEditor.canRefreshSelectedLayerFromModelExactly()` succeeds. This avoids
an unnecessary interpolation fetch while preserving the authoritative committed
packet, worker synchronization, compile request, and overview refresh.

This optimization is valid only after selection reconciliation reports no
change, and only for a non-background, non-automatic, unlocated default-master
selection. Interpolated or located layers, smart-component locations,
background layers, automatically aligned layers, reconciled selections, and a
failed exact-refresh probe MUST fall back to `fetchLayerData()`. Local undo and
redo may skip their fallback fetch only after the same exact refresh succeeds.

## Committed Packet Lifecycle

For normal edit-time convergence, including undo and redo, the authoritative
event chain is:

```text
Local mutation -> derive authoritative Yjs delta -> local post-commit reactor on that delta -> send delta -> remote apply delta -> remote post-commit reactor
```

Interpret each step literally:

1. Local mutation updates the authoritative local Yjs document first.
2. The committed binary Yjs delta is derived from that committed Yjs state.
3. The local sender enters the shared committed-change funnel from that same
   authoritative delta.
4. That same delta is broadcast to linked windows and collaboration peers.
5. Receivers apply the delta to their local Yjs document.
6. Receivers then enter the same committed-change funnel, with receiver-only
   visual compensation allowed before the shared post-commit work begins.

Important nuance: this is not a plain "mutate JS model first, then encode to
Yjs" flow. For steady-state editing, undo, and redo, Yjs is authoritative. The
local JSON/model view is patched from the committed Yjs state immediately after
that mutation, and the local and remote post-commit reactors are both supposed
to consume the same authoritative Yjs packet rather than parallel ad hoc local
reaction paths.

Undo and redo add one extra constraint on top of that chain: if history UI
state needs a coarse control row in the change log, that row is history-only.
The packet observed by post-commit consumers must still carry the same semantic
entry *shape* as the original forward edit (cloned entries with
`historyAction` set to undo/redo). For cascade-capable packets, the
authoritative Yjs delta is origin restore plus freshly settled dependents
(rule 18b), not a mechanical invert of the stored cascade snapshots.

## Boundary-Crossing Budget

`FontManager` exposes `getBoundaryCrossingStats()` and `resetBoundaryCrossingStats()` so tests and the AI profiling harness can pin per-edit traffic across the JS ↔ Rust/worker boundary. The locked-down budget is:

| Operation                                                      | `submitBatchCalls` | `layersTransmitted` | `glyphsTransmitted` | `fullFontCrossings` |
| -------------------------------------------------------------- | ------------------ | ------------------- | ------------------- | ------------------- |
| Single-layer commit (keyboard / drag-end)                      | `1`                | `1`                 | `1`                 | `0`                 |
| Multi-glyph cascade commit (e.g. anchor cascade, metrics keys) | `1`                | `N` (changed)       | `M` (distinct)      | `0`                 |
| Receiver committed replay with `workerReplayTargets`           | `1`                | `N` (targets)       | `M` (distinct)      | `0`                 |
| Undo / redo with `workerReplayTargets`                         | `1`                | `N` (targets)       | `M` (distinct)      | `0`                 |
| Font open / external reload                                    | `0`                | `0`                 | `0`                 | `1`                 |

Steady-state lock-down: 50+ sequential commits MUST keep the per-commit budget flat at `(1, 1, 1, 0)`. Any growth indicates a regression. For keyboard outline, anchor, sidebearing, remote replay, and undo/redo commits, that one batch is the authoritative forwarded Yjs delta via `forwardWorkerYjsUpdate`; no committed path may send a second whole-layer worker rewrite before compile. `tests/font-manager.test.js` (`FontManager boundary-crossing budget`) and `tests/change-bridge-init.test.js` lock this directly.

## History-Notification Budget

Every change-log notification fires `bridge.onChangeLogUpdate` listeners synchronously inside the transaction commit, so any per-listener cost is paid as freeze time on the commit critical path. The locked-down rules:

- **`computeHistoryState` MUST be incremental.** It is keyed by the `_changeLog` array reference (a `WeakMap`) and folds only the new tail entries on each call. The cache is invalidated automatically when `_changeLog` is reassigned (font open, restore, reset). The change-log MUST stay append-only between resets — no `splice`/`pop`/`shift`/`length=N`/in-place reorder. Any code that needs to mutate it in place must reset and rebuild instead.
- **`computeHistoryState` MUST NOT materialize per-item array views inside its entry loop.** `touchedPaths`, `historyTargetKeys`, and `workerReplayTargets` are O(N²) hazards (each new path/target re-spreads the full set). They are materialized exactly once per visible item in `stripMutableHistoryItem`, after the fold is complete.
- **`history-view.render()` MUST be coalesced** behind `requestAnimationFrame` for all change-log-driven invocations. Multiple commits in the same animation frame produce one DOM rebuild. Synchronous `render()` calls are reserved for explicit user-driven scope/breadcrumb changes.
- Tests in `tests/change-bridge.test.js` (`buildHistoryStackItems scales sub-linearly...` and `incremental cache correctly applies undo/redo entries...`) lock in both the perf budget and the correctness of the incremental fold under undo/redo stack rotation.

## Window-Sync Budget

The local-update broadcast in `window-sync.ts` runs synchronously inside the
Yjs transaction. Encoding the full Yjs document (`Y.encodeStateAsUpdate` plus
`Array.from()` to send over `BroadcastChannel`) for a 3 MB font costs
100–200 ms per commit and was the dominant freeze source on routine outline
edits.

- The `yjs-update` broadcast MUST omit the `fullState` payload on the ordinary
  edit hot path, even when the sender has known peers. Encoding the full state
  inside a local edit transaction is too expensive for routine linked-window
  edits.
- Local `yjs-update` broadcasts MUST be microtask-batched. Multiple Yjs updates
  emitted during the same event-loop turn merge into one Yjs update payload and
  one concatenated `changeLogEntries` array, producing one
  `BroadcastChannel.postMessage` and one receiver refresh.
- Receiver-side `yjs-update` handling MUST also be microtask-batched. Multiple
  incoming messages in one turn merge into one `applyRemoteUpdate` call so the
  replay targets reach `syncRustCacheAndRefreshCanvas` as one batch.
- Broadcast payloads SHOULD use structured-cloned `Uint8Array` data instead of
  `Array.from()` number arrays. Receivers may accept the older number-array
  shape for compatibility.
- Live `yjs-update` payloads MUST carry only the Yjs delta plus the associated
  `changeLogEntries` replay metadata. They MUST NOT include `fullState`, layer
  repair snapshots, or any other side-band repair state. Partial layer snapshots
  must be rejected or applied non-destructively at the producer boundary; the
  collaboration transport must not repair malformed transactions after the
  fact.
- New peers still bootstrap correctly via the `full-state-request` /
  `full-state-response` round-trip in `_handleMessage`. They do not depend on
  the bundled `fullState` from `yjs-update` for first-time bootstrap.
- Tests in `tests/change-bridge.test.js` (`no peers: yjs-update broadcast omits
fullState...`, `with a peer: yjs-update broadcast omits fullState...`,
  `same-tick local updates are batched...`, and the partial layer snapshot
  producer-invariant tests) lock the budget and the no-repair live-update
  contract. The same suite also locks layer-scoped undo after inbound batching.

## CompiledEditFunnel — Single Post-Commit Reaction Owner

`CompiledEditFunnel` (`webapp/js/compiled-edit-funnel.ts`) replaces the previous pattern where `requestCommittedEditingFontCompile` was a standalone function with its own guard logic, and `FontManager.scheduleFullCompileDebounce` was a separate timer that could race with the Yjs commit funnel.

### Architecture

Every committed Yjs packet, local or remote, enters `processCommittedEdit()` in the funnel. The funnel:

1. **Guards:** Skips the startup `changeVersion === 0` bootstrap noise.
2. **Filters:** Non-compiling edit types (`'guide'`) return immediately — no context is set, no compile is requested.
3. **Builds compile context:** Derives `{ changeSource, editType, dataFreshnessMode }` from the committed packet being processed, not from ambient `lastChangeSource` / `lastEditType`.
4. **Requests compile:** Calls `requestRecompileWithoutDataChange({ compileContext })` + `autoCompileManager.checkAndSchedule()` so the context is snapshotted against the resulting `compileRequestVersion`.
5. **Force-trigger:** For remote, undo, and redo, awaits `forceTrigger()` for immediate compilation.
6. **Waits for completion:** Only when `forceTrigger` is available (`waitForCompletion` + `canForceTrigger`).
7. **Arms deferred full compile:** For local fast-path edit types only, calls `armDeferredFullCompile()` which replaces `FontManager.scheduleFullCompileDebounce()`; remote packets and already-full packets do not arm a trailing full compile.

### Non-Compiling Edit Types

The following edit types are stamped by the writer and routed through the funnel, where they are skipped without setting compile context or requesting compilation:

- `'guide'` — layer-scope guides are editing-time helpers that don't affect font compilation. Master-scope guides are similarly non-compiling.

These edit types still sync to Yjs for undo/history and collaboration, but the funnel's `processCommittedEdit` returns early for them.

### Deferred Full Compile Integration

The deferred full compile timer lives inside the funnel (`armDeferredFullCompile`). It is armed after local `processCommittedEdit` calls for fast-path edit types (`outline`, `anchor`, `kerning-value`, `kerning-groups`). Remote packets and `editType === null` packets do not arm it; linked windows only run their immediate remote editing compile. The timer:

1. Is cancelled and re-armed on each new edit.
2. Postpones itself if a drag is active (`draggingSomething === true`) or a text-mode kerning preview burst is active (`GlyphCanvas.hasActiveTextModeKerningPreviewBurst()`).
3. Skips if the last compile was already `'full'` (`lastCompilationMode === 'full'`).
4. Waits for the already-forwarded authoritative Yjs update to settle in the worker cache; it never serializes the live model or clears a pending JSON marker.
5. Fires `processCommittedEdit('deferred-full', null)` through the same funnel queue.

This eliminates the race between the old `scheduleFullCompileDebounce` and the committed-change funnel, because the deferred request enters the same serialized processing path as all other compile requests.

## Scheduling Details

### Undo/redo

Undo/redo must emit the same canonical local Yjs packet as forward edits and
then wait for the shared committed-change funnel to finish. The funnel owns the
worker-sync wait, editing-font compile wakeup, optional force-trigger wait,
overview invalidation, and trailing full-compile debounce. `runBridgeUndoRedo()` may capture transient
local visual context such as the pre-undo width for canvas anchoring, but it must
not run a separate Rust-cache refresh, compile request, or overview refresh.

Undo/redo must rely on the already-forwarded incremental Yjs worker update. If
the recorded history entries also carry explicit layer replay targets, those are
metadata for compile-context inference, drift inspection, and Rust-side targeted
cache patching only; they MUST NOT trigger a second worker mutation before
compile.

narrow metadata for the committed funnel to avoid unnecessary work around the
already-authoritative Yjs update. Missing replay targets or worker-sync timing
issues must be fixed inside the incremental path; they must not trigger any
full-state repair resend.

When the undone/redone history item replays an interactive edit, undo/redo must
derive `lastEditType` and `lastChangeSource` from the same semantic change
metadata rules as the original forward entries. In practice that means anchor
replays set `('anchor', 'keyboard-anchor')`, outline replays of point and
component edits set `('outline', 'keyboard-outline')`, sidebearing replays set
`(null, 'keyboard-sidebearing')`,
kerning-value replays set `('kerning-value', 'keyboard-kerning-value')`, and
kerning-group replays set `('kerning-groups', 'keyboard-kerning-groups')`
before requesting the editing-font compile. Undo/redo must not collapse these
cases into a generic replay-only source such as `keyboard-undo-redo`, because
that severs the exact semantic parity with forward editing that the policy
requires. The trailing debounced full compile still resets `lastEditType` to
`null` for correctness, but the immediate editing-font compile must benefit
from the same fast path as the original edit.

Anchor-edit history entries (both mouse-drag and keyboard) must carry
`workerReplayTargets` that include all downstream auto-composite glyph/layer
pairs. For keyboard anchor nudges, `rebuildAutomaticCompositesForCurrentEditedGlyph`
must run before `saveLayerData` so the model is current when the Yjs entry is
recorded, and `_syncCurrentGlyphToYDoc` must pass the collected targets. This
is required so undo stays on the incremental path. Any code that would otherwise
have forced a full-document Rust resync is a regression and must be removed.

### Interactive layer saves

`FontManager.saveLayerData()` still prepares the local model state for keyboard saves and drag-finalization saves, but committed post-commit reactions now belong to the authoritative Yjs packet rather than the save helper itself. The required responsibilities are:

1. It marks the font dirty immediately.
2. It may record transient local edit metadata (`lastChangeSource` / `lastEditType`) for legacy scheduling paths, but it does not arm `scheduleFullCompileDebounce()` or own the trailing full compile.
3. It MUST NOT dispatch the committed overview refresh or wake the committed editing compile directly. Those now run only after `PatchSyncEngine` emits the authoritative committed Yjs packet and the shared committed-change funnel consumes it.

When the shared local committed-change funnel can infer an interactive fast-path edit from the authoritative committed entries, it MUST prefer that inferred interactive source over any stale trailing full-compile marker already left on `FontManager`. A prior `debounced-post-interaction-full-compile` source must never downgrade the next committed keyboard or mouse fast-path compile to `full`.

#### Synchronous local commit sequence

For interactive outline, anchor, and sidebearing saves, the local sender must
finish one synchronous commit phase before any async propagation, worker-cache
refresh, or compile wakeup begins.

The required sequence is:

1. Serialize the edited layer payload into canonical storage form.
2. Commit that serialized layer into `currentFont.babelfontData` in place,
   without replacing the stored glyph or layer objects.
3. Sync the object-model layer from that same serialized stored layer and
   invalidate any layer-local caches.
4. Mark only the serialized-string cache (`babelfontJson`) as stale when the
   edit path is allowed to defer string regeneration. The authoritative JS font
   object (`babelfontData`) must already be current at this point.
5. Emit the authoritative committed Yjs packet from that already-committed
   local state.
6. Let the shared committed-change funnel own the authoritative async
   post-commit reactions: compile wakeup, linked-window propagation, cloud
   propagation, and overview invalidation. Sender-local save helpers may still
   perform narrow worker-cache priming needed for the local interactive path,
   but that work must happen strictly after steps 1-5 and must not replace or
   race the authoritative Yjs-driven post-commit reactions.

This ordering is mandatory because tests and post-commit consumers may inspect
`currentFont.babelfontData` immediately after `saveLayerData()` returns. A
state where the editor layer and Yjs delta are current but `babelfontData`
still contains the pre-edit layer is a bug.

While the pointer is still down for a mouse drag, the live editing compile path must remain active. What must stay suppressed is only the trailing full editing-compile side and the JSON/model sync required to feed it. Mid-drag pauses may continue to produce editing compiles, but must not flush `pendingBabelfontJsonSyncAfterDrag` until the drag ends.

Outline point/component drags now mirror the anchor-drag pattern during the active drag: they keep the model current, batch-refresh the edited layer plus visible metrics-key dependents into a sparse preview layer overlay with `stageLiveDragPreviewFromModel()` / `applyPreviewLayerOverlay`, and request recompilation without routing every drag tick through `saveLayerData()`. The final `saveLayerData('mouse-drag-outline')` still fires on mouseup for Yjs/collaboration sync, undo history, and authoritative worker cache mutation; the committed packet stamps `editType: null` so the funnel runs one full editing compile rather than incomplete outline-only plus deferred full.

Anchor drags skip `saveLayerData()` entirely during the drag. Instead, the shared cascade engine prepares on every tick (`prepareLiveVisibleAnchorDependentRefresh` → `computeLayerRecompositionClosure({ scope: 'visible' })`), then the funnel is **stage-only**: it coalesces to the newest cached `allTargets` via the single-flight queue and, after a successful `stageLiveDragPreviewFromModel`, requests a live compile. A successful stage must wake compile even if newer ticks arrived during the await; the next queued request will stage+compile again. Empty/failed stages return `false` and skip compile. That same live path must route sender overview invalidation through the shared glyph-overview refresh helper used by the bridge funnel, preserving the immediate-refresh hint while deduplicating glyph-name expansion and dependent-composite handling with the receiver path. On mouseup, `isDraggingAnchor` stays true through drain → Yjs, then the editor explicitly `clearLiveDragPreview()` (no overlay preserve) so drag-2 cannot inherit an orphaned physical generation. Commit-time `scope:'all'` closure must still put automatic dependents into `recomposeTargets` / `changedLayerTargets` even when rebuild is a no-op after live converge (same persistence rule as sidebearing); mouseup keeps the live `_anchorAffectedGlyphNames` set (no second `rebuildAutomaticCompositesForCurrentEditedGlyph` before the closure) and passes `_lastLiveAnchorRecomposeTargets` into `resolveLayerSyncTargetsFromClosure`. The commit-time closure is the only all-scope automatic rebuild. Layout-cache invalidation for that rebuild is source ∪ component dependents ∪ visible metrics-key prerequisites, not every glyph currently on canvas. The final `saveLayerData('mouse-drag-anchor')` fires on mouseup for the Yjs/collaboration sync and undo history, and the resulting committed Yjs packet then drives the same centralized post-commit compile/overview path as every receiver window.

Sidebearing drags skip `saveLayerData()` during the drag, mirroring the anchor drag pattern. Pointer samples coalesce into one animation frame that mutates, rebases the pointer baseline after pan/advance sync, and paints once. Each coalesced frame syncs the source layer and runs **one** `computeLayerRecompositionClosure({ scope: 'visible' })` (transitive retain expansion included), refreshes advances only for `source ∪ recomposeTargets` (not invalidate-only manuals), and caches `allTargets` for preview. The live funnel stages the latest coalesced targets via `stageLiveDragPreviewFromModel` with compile-facing (`toCompileJSON`) serialization and must not re-run the closure. After a successful nonempty stage it requests compile. Preview results use a latest-applied lane: a completed stage may apply while a newer stage is queued, and only a result older than the current painted preview is rejected. This prevents revision supersession from delaying visible recomposition until pointer idle. During the interactive sidebearing session, preview font swaps must update outlines without reshaping the text run and without issuing an independent compile repaint; live advances and bbox-center anchoring remain owned by the interaction frame. The same active-glyph bbox-center anchor is mandatory for explicit sidebearing forward edits and their undo/redo replays: capture it before the mutation or history operation, then restore it after model and live-advance refresh and before the single repaint. This visual contract must not depend on side-specific packet or history metadata. On mouseup, `isDraggingSidebearing` stays true through drain → final refresh → Yjs so in-flight funnel stages still compile under that no-reshape contract; the editor then drains the live funnel, runs **one** `scope: 'all'` closure in `refreshFinalSidebearingWorkerStateBeforeCommit` (stashed for serialize-only sync — no second full closure), applies delta-only advance pan vs the last live advances, and syncs `source ∪ recomposeTargets` through the authoritative Yjs packet (logical `toJSON`). Mouseup then explicitly `clearLiveDragPreview()` (in addition to `apply_yjs_update` clearing the overlay) so drag-2 cannot inherit an orphaned physical generation; a funnel stage that finishes after session death must also clear that orphan. Yjs worker mirrors remain logical. Compile-facing automatic data comes from (1) the preview overlay during live drag and (2) Rust compile-read bake of logical `=+/-=` layers when building the font handed to fontc. Each preview stage replaces its physical overlay atomically; overlay layers are skipped by Rust bake. The final `saveLayerData('mouse-drag-sidebearing')` fires on mouseup for the Yjs/collaboration sync and undo history.

Keyboard sidebearing adjustments rely on the authoritative bridge Yjs packet (and live preview overlay while dragging) for downstream glyphs instead of any whole-layer worker rewrite or full-document path.

### Deferred full compile (CompiledEditFunnel)

The deferred full compile timer lives inside `CompiledEditFunnel.armDeferredFullCompile()`. It is the correctness pass after interactive edits whose committed packet still used a fast-path `editType` (`outline`, `anchor`, `kerning-value`, `kerning-groups`). When the timer fires, it requests a `'full'` compile through `processCommittedEdit('deferred-full', null)`, which enters the same serialized funnel queue as all other compile requests. This resets `lastEditType` to `null` so the compilation mode becomes `full` with features and kerning restored.

Local preview-backed outline, component, and anchor commits (and structural outline commits that share those change sources) stamp `editType: null` like sidebearing, so they run one authoritative `full` compile at commit time and do **not** arm this deferred timer. Live drag/keyboard preview still uses incomplete `outline-only` / `anchor-only` compiles with the live-preview freshness mode; only the post-commit middle incomplete authoritative compile is removed.

If an outline or anchor drag is still active when the timer fires (for edit types that still arm it, such as kerning or remote-inferred outline packets), it re-arms itself and waits until the drag has ended before requesting the cached-worker compile. It also re-arms while a text-mode kerning value preview burst is active, so a trailing full reshape cannot clobber an uncommitted pair preview. The pending `pendingBabelfontJsonSyncAfterDrag` marker is not a worker-staleness signal and remains untouched; serializing it during an active drag would create a stale full-model baseline and break undo.

The timer is cancelled and re-armed on every fast-path edit (`'outline'`, `'anchor'`, `'kerning-value'`, `'kerning-groups'`) that enters the funnel. This means rapid edits only trigger one deferred full compile after the last edit + 500ms delay.

### Text input

Text input does not go through `saveLayerData()`. Instead it:

1. Recomputes the editing subset.
2. Marks `lastChangeSource = 'text-input'`.
3. Calls `compileEditingFont()` directly so no full font JSON transfer is needed.
4. Schedules `scheduleTextInputFullCompile()` to restore a full compile after typing settles.

### OpenType feature source edits

OpenType feature source edits in the font-info Features editor are font-wide source changes, so they must stay on the full compile path rather than any outline or text-input fast path. They must still enter the shared patch/Yjs funnel before recompilation so Rust receives the same authoritative Yjs update as every other edit.

The editor commits and recompiles feature code in three cases:

1. Immediately on `Cmd+Enter` / `Ctrl+Enter`.
2. Immediately when the Ace editor loses focus.
3. Automatically after 5 seconds with no further typing.

All three triggers must use the same commit path: write the current Ace buffer through the patch bridge, mark the font dirty, wait for the corresponding Yjs worker update to land, and call `recompileEditingFont()`. That recompilation must validate feature-code edits against the full validated babelfont JSON rather than the subset-retained editing font, so glyph references outside the current text subset still resolve correctly. Blur and explicit commit must cancel any pending idle timer so one edit burst produces at most one automatic compile.

The cached worker path must validate raw feature source before applying the editing filter pipeline. Filters such as glyph retention may normalize or discard feature statements, so feature-code commits first compile the full cached Rust font for validation, then continue with the filtered editing-font compile only if that raw validation succeeds. This validation still reads the Rust-side Yjs/CANONICAL_JSON cache; it must not send a full babelfont JSON string from JavaScript.

## Worker Cache Policy

### Rust Worker Cache Authority

The Rust worker cache chain has one authoritative direction during steady-state
editing:

```text
Y.Doc -> CANONICAL_JSON_CACHE -> FONT_CACHE -> subset/filter/layout/compile caches
```

`CANONICAL_JSON_CACHE` is the Rust worker's materialized JSON view of the
authoritative Yjs document. `FONT_CACHE` is only the typed `babelfont::Font`
derived from that JSON for operations that need the Rust object model. After any
edit-time Yjs update changes canonical JSON, `FONT_CACHE` and all feature,
subset, filtered-font, layout-closure, and outline caches derived from it must be
invalidated or rebuilt from `CANONICAL_JSON_CACHE`. Editing code must not patch
`FONT_CACHE` as a competing source of truth for font-wide data. Feature-code
validation must read the latest Yjs-derived canonical state before the subset
editing compile runs.

The fast path depends on these rules staying true:

1. Drag and keyboard layer edits use the incremental sentinel JSON path in `font-compilation.ts` rather than sending the full babelfont JSON to the worker.
2. `applyYjsUpdate` is the authoritative edit-time worker update channel for both local and remote changes.
3. `applyJsonPatches` is not part of the edit-time worker path. Interactive cache updates must reach Rust through the already-issued Yjs worker sync rather than a parallel JSON-patch channel.
4. When the bridge already holds the authoritative binary Yjs delta plus layer replay metadata, the worker path must forward that original delta directly. It may derive local fingerprint bookkeeping from the object model, but it must not rebuild a second Yjs update for the same edit.
5. The editing subset key is reused when unchanged so subset font caches stay hot. Layout closure uses a separate feature-sensitive closure key and must not include visual font-cache epochs for ordinary outline, anchor, sidebearing, component, guide, or layer-visual edits.
6. Full `store_font()`, `storeFontJson`, `seedYdoc`, or `initYdoc` are reserved for font open and no-bridge external-reload bootstrap, not for interactive editing, active-bridge external reload, undo, redo, Python execution, feature-code commits, or linked-window edit replay.
7. Dormant compatibility branches that resend a full document during normal editing must be deleted rather than retained as safety valves. If the incremental pipeline is insufficient, fix the pipeline.
8. Live drag preview uses `applyPreviewLayerOverlay`, `primePreviewLayoutClosureCache`, and preview compile functions backed by a sparse Rust preview overlay. Preview updates may compile immediately, but they MUST NOT create or clone a preview Y.Doc and MUST NOT mutate authoritative `Y_DOC`, `CANONICAL_JSON_CACHE`, `SUBSET_JSON_CACHE`, `FONT_CACHE`, `SUBSET_FONT_CACHE`, or the authoritative layout-closure sentinel. The first live-drag preview compile after overlay-clear (or reload) MUST adopt `LAST_LAYOUT_CLOSURE_CACHE_KEY` into the preview lane instead of re-priming a new closed glyph set; re-priming remaps HarfBuzz glyph IDs against the already-shaped run. `clearPreviewLayerOverlay` discards only the sparse overlay; mouseup, undo, redo, remote changes, and keyboard edits converge only through `applyYjsUpdate` packets emitted or forwarded by the bridge.
    Live overlay traffic uses a dedicated `workerPreviewSendQueue`. Authoritative `sendWorkerYjsUpdate` MUST drain that preview queue (including `clearLiveDragPreview`) before posting `applyYjsUpdate`. Overlay apply and Yjs apply MUST NOT share one FIFO that can delay a commit behind later preview ticks, or delay a preview behind an unrelated Yjs send except for that explicit pre-commit drain.
    Compile-facing preview layers are `toCompileJSON` plus `normalizeLayerForRust`. They MUST NOT run `serializeLayerForStorage` / `toRestingLayerJson`. The worker JSON-stringifies overlay records and metadata for the existing `apply_preview_layer_overlay(&str, &str)` wasm boundary.

### Layout Closure Cache

The layout closure cache represents the closed glyph set needed for the current editing text and active OpenType feature selection. It is not a cache of glyph outlines. Visual edits update the glyph data inside the existing closed set and therefore must not clear or re-prime the closure. Live-drag preview compiles use a separate last-closure pointer; when that pointer is cold they must adopt the authoritative pointer rather than compute a new closed set.

The worker may re-prime layout closure only when one of these inputs changes:

- The editing text/subset changes, producing a different subset glyph key.
- The selected OpenType feature set changes, producing a different layout-closure key.
- Feature source data or glyphset-level structure changes in a committed Yjs packet.

Layer-scoped visual updates forwarded through `applyYjsUpdate` must pass `invalidateLayoutClosure: false`. This applies equally to local commits, linked-window replay, undo/redo replay, and Python edits that only touch visual layer data.

If `compile_cached_font_from_last_layout_closure()` reports that no layout closure is primed while the JS worker sentinel believed the closure was reusable, the worker must treat that as stale closure metadata and re-prime from the current Yjs-backed `subsetGlyphs`/layout-closure key before retrying the cached compile. This is not a full-document fallback and must not rebuild state from JSON; it only restores the Rust closure cache for the already-authoritative worker Y.Doc.

Any change that introduces or increases any full-document transfer during normal editing is a regression unless explicitly documented and approved for bootstrap-only behavior.

## Collaboration Metadata Policy

There are two distinct mutation formats in the system, and they serve different boundaries:

1. Rust worker boundary during editing: incremental Yjs updates against the worker Y.Doc only. Full `storeFontJson`, `seedYdoc`, or `initYdoc` are reserved for bootstrap and no-bridge external-reload initialization, not for normal editing recovery or active-bridge external reload.
2. Collaboration/history metadata boundary: semantic change descriptors whose paths use stable glyph names and layer ids where human-readable or history-facing paths are needed.

The collaboration/history metadata format exists because history display, undo labels, replay-target hints, and cloud-side audit trails need stable semantic identity even when raw numeric array indices would be unstable. It accompanies the authoritative Yjs update; it is not the document-state transport between JS peers.

Required properties of every collaboration metadata entry:

- It describes the affected path or target using stable glyph names and layer ids whenever glyph or layer identity is involved.
- It may attach `workerReplayTargets`, edit-source metadata, and human-readable summaries.
- It may be derived from JSON Patch or named forward/inverse patch pairs when a producer, such as Python snapshot diffing, needs that conversion internally.
- It must not be used to replay, rebuild, or repair font data during ordinary linked-window or cloud convergence. The Yjs update alone defines document state.

Only binary Yjs updates are supported for collaboration, linked-window sync, cloud convergence, and steady-state worker convergence. Metadata is permitted only as a companion record.

### Required edit funnel

All persisted font-data edits must flow through the patch system so change-log history, linked windows, cloud durability, undo/redo, and replay all see the same canonical mutation stream.

For all non-exception persisted edits, the bridge finalizes transactions in this order:

1. Apply the direct edit to the in-memory JSON/model.
2. Derive the direct mutation operations that describe that user edit.
3. Before the transaction is committed, inspect those direct operations for cascade triggers.
4. If the direct operations touched layer width or anchors, rebuild downstream automatic composites and metrics-key dependents inside the same open transaction.
5. Derive a second operation set for the cascade-only layer changes.
6. Commit one combined operation list, emit one authoritative Yjs update, and attach the corresponding semantic change metadata to that same committed packet.

Node-only outline edits must not trigger downstream recomposition by themselves. Downstream recomposition is keyed to anchor changes and width-affecting edits.

There are only two approved exceptions:

1. Live dragging may update the sparse worker preview overlay and trigger instant editing recompilation before the final patch-funnel commit lands. It must not update authoritative worker state before mouseup. The drag interaction must still commit through the patch system when the gesture is finalized.
2. Debounced feature-code editor recompilation may still auto-run after idle, but the commit itself must first enter the shared patch/Yjs funnel. Automatic recompilation is not an exception to the authoritative Yjs transport rule.

## Rendering Policy

1. `outline-only` compiles must skip HarfBuzz reshape and only swap the font blob plus repaint. This includes live drag preview compiles: the preview font is built with `skip_features` / `skip_kerning`, so reshaping would drop kerning before the active glyphs and jump the canvas. Width changes from keyed-sidebearing recomposition during outline drag are applied in JS via `refreshGlyphAdvancesLive` (and preceding-delta pan), not by reshaping.
2. `anchor-only` compiles must reshape text because anchor edits affect GPOS positioning.
3. `full` compiles continue through the existing complete render/update path.
4. `text-input` stays on its dedicated path because the font data is unchanged and only the shaped subset changed.
5. `kerning-only` compiles must replace the shaping-only HarfBuzz font, reshape text, and repaint. The compiled output must be a variable font with `fvar` (all layers processed) so HarfBuzz shapes at the correct multi-master instance.

## Rationale By Edit Type

### Outline edits

Outline edits only change glyph geometry. They can use the most aggressive fast path: incremental layer patching, the subsetted editing target, no feature compilation, no kerning compilation, no VARC generation, and no text reshape on the canvas. Live outline previews follow the same no-reshape rule; when dragging a node on a layer with keyed sidebearings changes visible-layer widths, advances are patched in JS before the preview compile returns.

### Sidebearing edits with cascading metrics keys

Sidebearing edits that trigger metrics-key cascades still use the incremental worker fast path, but they must rebuild downstream automatic-composite layers for the same affected scope that anchor edits use. During drag that scope stays visible-only so hidden dependents remain deferred; preview deltas are pushed only to the sparse preview overlay. On mouseup the filter is removed and the full downstream set is recomputed before Yjs sync, and the committed incremental Yjs packet is what mutates authoritative worker state. The committed Yjs packet is stamped with the exact sidebearing source (`mouse-drag-sidebearing` / `keyboard-sidebearing`) and requests a full editing compile so reshaping and advance updates land from the same packet instead of a later fallback.

### Anchor edits

Anchor edits still benefit from incremental layer patching and cached subset reuse, but they cannot skip all feature work because GPOS mark attachment must stay correct. They also keep kerning enabled, because this path reshapes text immediately and the live editing font must retain complete positioning data. They keep a live compile path, but use `anchor-only` rather than `outline-only`.

### Generic keyboard saves

Generic `keyboard` saves do not carry an edit-type suffix, so they fall back to full compile mode while still benefiting from the interactive worker path when the save came from `saveLayerData()`.

### Kerning edits

Kerning edits (both value and group membership) use `kerning-only` compilation mode with `produce_varc_table: false` but must NOT set `skip_outlines: true`. In the babelfont fontc pipeline, `skip_outlines: true` causes `create_glyph_ir_work` to skip every non-default master's layer (`if self.options.skip_outlines && !location.is_default() { continue; }` in `glyphs.rs`). This means only the default master's layer data enters the IR, fontc sees only one source per glyph, and the output font is a STATIC font without an `fvar` table. When this font is used as the HarfBuzz shaping font during the kerning-only compile, `setVariations()` becomes a no-op, and shaping uses only the default master's kerning — producing incorrect glyph positions for any non-default master instance. Removing `skip_outlines` from the option overrides ensures fontc processes all layers, produces a variable font with `fvar` and GPOS kerning variations, and HarfBuzz shapes at the correct instance position. The compiled outlines in the font are unused for rendering (outline drawing uses the separate main `hbFont`), so the performance cost is limited to IR processing of additional layers for the subsetted font.

### Text input

Text input changes the shaping subset rather than the font data. It therefore bypasses `saveLayerData()`, reuses the cached worker font, compiles only the updated editing subset, and schedules a trailing full compile for correctness.

### Linked windows

Linked windows share the same font model as the main window via Y.Doc sync. They need editing compiles for live canvas feedback, while binary export and assistant analysis use an isolated worker seeded from settled committed state on demand.

**Committed-change funnel:** Committed local packets and committed remote packets both enter the same serialized post-commit funnel. Local packets enter it immediately after the authoritative Yjs update is emitted. Remote packets enter it immediately after the update is applied. The shared funnel owns compile wake-up and overview invalidation for both origins so sender and receiver windows react to the same committed metadata instead of maintaining parallel reaction code. The funnel is implemented by `CompiledEditFunnel.processCommittedEdit()` (`webapp/js/compiled-edit-funnel.ts`), which replaces the previous `requestCommittedEditingFontCompile` function.

**Editing compile efficiency:** When the committed-change funnel handles a remote packet, it extracts edit-type metadata and `workerReplayTargets` from the change log entries and uses them to:

1. Wait for the already-forwarded authoritative worker Yjs update and any pre-existing chained worker-cache promise to settle, without scheduling a second replay-target repair packet.
2. Infer the original edit type (`anchor` / `outline`) so the linked window's editing compile uses the matching fast-path compilation mode (`anchor-only` / `outline-only`) instead of always falling back to the slowest `full` mode.

Linked-window/cloud replay must rebuild change-log entries from the named forward/inverse patch pairs, not from any worker-local cache transport. The worker Yjs update is a receiver-local cache refresh detail; it is not the cross-window source of truth.

For local commits, the same funnel must wait for the already-forwarded worker Yjs update to land and for any chained worker-cache promise that already exists to settle before requesting the editing compile or invalidating overview tiles. That preserves the sender's fast path while keeping the compile trigger and committed overview refresh tied to the authoritative committed packet rather than to `saveLayerData()`.

**High-priority compile context cleanup:** `lastChangeSource` and `lastEditType` are transient compile-request context only. They must be set only by `CompiledEditFunnel.processCommittedEdit()` before requesting an editing compile. Edit handlers, drag live refresh paths, `saveLayerData`, and any other code in the edit pipeline must not call `setEditingCompileContext` — the funnel is the sole owner of compile context. The captured request context must be cleared after the compile reads it (by `compileEditingFont`), unless a newer request has already replaced it. Mouse and keyboard edits of outlines, anchors, components, and sidebearings, plus their undo/redo replays, must all leave the same clean post-compile state. No edit type may leave a stale source/type pair that changes the compile mode of a later edit.

Property-panel sidebearing key edits follow the same rule as outline, anchor, component, and sidebearing-handle edits. The sender may set `lastChangeSource` / `lastEditType` to arm the correct interactive context and trailing full compile before committing the model transaction, but it must not call `refreshGlyphsAfterModelBatch`, `requestRecompileWithoutDataChange`, or `autoCompileManager.checkAndSchedule` as a second committed reaction when `PatchSyncEngine` is active. The sparse committed Yjs update and the shared funnel own the immediate editing-font compile wake-up. The same prohibition applies to component property-panel commits (automatic alignment, transform, anchor override) via `finalizeComponentPropertyPanelMutation`: with the bridge active those commits must not call `refreshGlyphsAfterModelBatch`, because that path builds a mirror-authored delete/recreate layer update that diverges the selected layer's CRDT identity from the bridge document and later undo/restore packets cannot repair it.

The receiver must refresh the worker cache before requesting its remote editing-font compile. Requesting a compile before the cache refresh completes can compile against stale Rust cache data and then immediately request a second compile. The linked-window remote path therefore schedules one editing compile after `syncRustCacheAndRefreshCanvas` has applied the replay targets or completed its fallback refresh.

For sidebearing edits that update downstream metrics-key dependents, the sender must sync the full affected layer batch through `syncLayersFromJson`, not only attach `workerReplayTargets`. The receiver still rebuilds the object model from the patched Y.Doc via `Font.fromData`, but that Y.Doc patch must include every affected layer so linked windows see the same downstream layer state that the Rust worker cache receives. Batched keyboard sidebearing entries may carry a generic transaction label such as `Arrow key`; in that case, the committed packet must still carry the explicit stamped compile metadata (`compileChangeSource = keyboard-sidebearing`, `compileEditType = null`) so receivers request the same full committed compile instead of guessing from labels.

**Echo gate (Y.Doc broadcast filter):** The `ChangeBridge` constructor's Y.Doc `update` listener uses a whitelist of known local edit origins (`USER_EDIT_ORIGIN`, `FONT_EDIT_ORIGIN`, `GLYPH_EDIT_ORIGIN`, `HISTORY_REPLAY_ORIGIN`, and `LAYER_EDIT_ORIGIN_PREFIX`-prefixed origins) to decide which updates to broadcast to other windows. Yjs CRDT reconciliation updates have `origin = undefined` and must NOT be broadcast, or they create a ping-pong echo loop between windows.

The linked window's editing font is recompiled because each window has a different editing subset (the glyphs visible in that window's editor view). The compilation uses the same fast-path mode as the originating edit, keeping it efficient.

## Non-Regression Requirements

The following are required and should be covered by tests or explicit review whenever compilation code changes:

1. `mouse-drag-outline`, `mouse-drag-sidebearing`, and `mouse-drag-anchor` continue to wake live editing compilation during drag. Live sidebearing stamps `editType: 'sidebearing'` (outline-only fontc flags, not an outline alias). Committed packets for those sources stamp `editType: null` so the funnel runs one authoritative `full` compile (deferred full is not armed). Kerning-only compiles set `produce_varc_table: false` and do not set `skip_outlines`.
2. When a deferred full timer is still armed (kerning fast-path commits, or legacy/inferred `outline`/`anchor` packets), it must not execute while a drag is active (enforced by `armDeferredFullCompile` re-arming itself while `draggingSomething` is true) or while `GlyphCanvas.hasActiveTextModeKerningPreviewBurst()` is true, then compiles from the settled authoritative worker Y.Doc/cache without model serialization. A kerning-only or full `editingFontCompiled` reshape must call `reapplyTextModeKerningLivePreviewAfterReshape()` rather than clearing a newer uncommitted preview.
3. `keyboard-outline`, `keyboard-sidebearing`, and `keyboard-anchor` may wake editing compilation immediately through the sparse preview overlay lane while a nudge burst is still active, but they MUST emit exactly one authoritative Yjs commit after the keyboard idle debounce. That committed packet stamps `editType: null` and enters the shared funnel as one `full` compile.
4. Interactive layer edits continue to use `update_cached_layer()` rather than full font JSON transfer in the steady state.
5. The editing compile continues to use the subsetted `editing` target before fontc.
6. `outline-only` still skips reshape and `anchor-only` still reshapes.
7. Text input still uses the subset-only fast path and still schedules a deferred full compile.
8. Live sidebearing edits with cascading metrics keys use `stageLiveDragPreviewFromModel` / `applyPreviewLayerOverlay` for the active drag/no-bridge refresh path instead of any whole-layer worker rewrite, and skip `rebuildAutomaticComposites` for downstream automatic-composite layers that only need width updates. Committed property-panel sidebearing key edits with `PatchSyncEngine` active rely on the sparse Yjs update and shared committed-change funnel instead of issuing a second local worker mutation.
9. Undo/redo of anchor edits uses `anchor-only` compilation mode and the already-forwarded sparse Yjs update (not full `storeFontJson`) when the history item carries `workerReplayTargets` for downstream auto-composite layers.
10. Undo/redo of sidebearing edits uses the stamped `keyboard-sidebearing` committed compile context, requests an immediate `full` editing compile, and keeps the active glyph's bounding-box center screen-stationary through the shared idle viewer lock (same capture/reapply/consume path as remote receive). Canvas paint is deferred while that lock is pending so a pre-reshape frame cannot flash the old pan; the consume after reshape is the first visible paint. It must not apply a separate undo-only live-advance patch or preceding-glyph pan. It still relies on the already-forwarded sparse Yjs update when the authoritative history item carries `workerReplayTargets` for every downstream layer affected by explicit metrics-key cascades and implicit automatic-component recomposition. Fallback history lookup must retain that complete closure rather than reducing it to the selected source layer; model, worker cache, and receivers must replay every target before advances and anchoring.
11. No editing, startup, or synchronization path schedules full binary compilation; binary export and assistant analysis are explicit isolated operations.
12. Linked windows recompile their own editing font on remote changes using the same packet-stamped committed compile context as the originating edit: anchor packets stay `anchor-only`, outline packets stay `outline-only`, and committed sidebearing packets run `full`.
13. OpenType feature source edits auto-compile on blur and after 5 seconds of typing idle, while cancelling the pending idle timer when an immediate commit already ran.
14. Every processed editing compile clears its captured `lastChangeSource` / `lastEditType` context unless a newer compile request has replaced it. The cleanup requirement applies uniformly to mouse, keyboard, undo, and redo for outline, anchor, component, and sidebearing edits.
15. Guide edits (both layer-scope and master-scope) do not trigger any font compilation. The writer stamps `editType: 'guide'`, and the funnel skips them. A packet with no `compileChangeSource` compiles full and logs; the funnel does not throw and does not infer a type.
16. `markDirty` does not schedule full binary compilation. It preserves only dirty-state and editing compile-request bookkeeping.
17. `saveLayerData` does not call `scheduleFullCompileDebounce`. The deferred full compile is owned by `CompiledEditFunnel.armDeferredFullCompile()` and enters the same serialized queue as all other compile requests.
