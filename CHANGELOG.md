# Unreleased

- **Keep-shape curve join**: Deleting an on-curve node between two cubics fits one curve across the gap (`Path.delete_keeping_shape` / `join_bez`). Tolerance 1000 covers typical joins; uneven handles use at least 128, even/inflected pairs at least 64. `Cmd/Ctrl+Alt/Option`-drag on a smooth point joins then re-inserts on that combined curve so the node slides along the outline.
- **Alt-drag corner points**: Holding Alt/Option while dragging a corner on-curve point moves it freely and leaves its handles in place, including when there is a curve on only one side. Smooth points still slide on the line between frozen handles.
- **Point size**: The Editing View title bar shows the on-screen text size in printer points (type-size icon), tied to canvas zoom. A ruler button opens a modal to calibrate the screen with a physical measurement (cm or inches); until then, 96 CSS pixels are treated as one inch. Thanks to @nicksherman (https://github.com/w3c/csswg-drafts/issues/614) and @graphicore (https://graphicore.github.io/varla-varfo/explorations/techniques/absolute_units_evaluation) for their work on the topic.
- **Multiline text**: Enter inserts a real line break in the editing-view text run. Line height is the font’s em square (`upm`) scaled by a line-height % field in the Editing View title bar (default 100%, matching CSS `line-height: 1` / InDesign solid leading); L/C/R alignment is relative to the longest line. Up/Down, line Home/End, and Cmd/Ctrl+Home/End move the caret like a standard editor. Vertical metrics, sidebearings, background tint, and kerning overlays follow the active glyph’s line. Shareable URLs store newlines as the two-character sequence `\n` in `text`, plus `lineheight` and `align` when they are not the defaults. Typing pans just enough to keep the caret in view, including after Enter when the new line would otherwise sit outside the viewport.
- **Path subtraction**: Closed paths can be marked Subtract in the property panel (`fip001-boolean`). They punch a hole in everything below them in shape order; later shapes sit on top. The editor canvas and glyph-overview tiles show the holes without rewriting nodes; cutter strokes are dashed. Canvas cutter fill covers the cutter except where later solids remain in the compiled font; solids below a cutter lose fill in the overlap. Compile flattens glyphs that use a cutter (including through components) and runs the same boolean. The flag round-trips on `.glyphs` save/open.
- **Arrange**: Canvas context menu **Arrange** moves mixed path and component selections as a unit (Bring Forward / Send Backward / Bring to Front / Send to Back), including on linked layers.
- **Path fill**: Editing View → View includes a Fill slider for outline-edit path (and cutter) fill opacity.
- **Python model mappings**: Record fields on the font object model (`name`, `location`, `metrics`, `kerning`, nested `font.names`, and the rest) wrap as live Python mappings. Attribute access works for identifier keys (`master.name.dflt`, `master.location.wght`, `master.metrics.XHeight`); kerning stays subscripted (`kerning["A:V"]`). `print`/`repr`/`to_py()` are Python dicts and lists, not `[object Object]`. Assistant and Konsole errors no longer mention the JS runtime. Glyph filters can read `glyph.anchors` (union of layer anchors). Documented in the Python API.
- **Cut / Copy / Paste**: Edit menu items Copy, Paste, Cut (`Cmd/Ctrl+C` / `V` / `X`) with dividers around the group. Cut and Copy enable when the focused view has a copyable selection. Paste (menu and shortcut) enables only when clipboard kind matches the focused view (glyphs → Overview, layer/SVG → outline edit, text → text mode); mismatches are ignored with no alert.
- **Assistant editor state**: The editor state given to the assistant now includes the active glyph name and the text-run caret (`cursorPosition`).
- **Delete anchors on variable glyphs**: Deleting an anchor now removes it from every interpolating layer and commits those layers, so fontc no longer fails with `BadAnchor NoDefault` and the canvas no longer stays frozen after the failed compile.
- **Auto QA**: Bundled corpus tables label likely missing components and anchors. When labels fire, the Editing View property panel shows a warning-only widget; hover explains the hint. The same messages are on `Glyph.qa`. Auto QA never auto-inserts outlines, components, or anchors.

- **Release CI**: Release workflow now runs graph chokepoint gates and a Prettier check before the webapp build and GitHub release.
- **Scroll Overview on open**: With Scroll Overview to Active Glyph on, opening in URL edit mode (`mode=edit`) scrolls the restored glyph into view in the overview after tiles load when it is visible under the active filter.
- **Pyodide 314.0.5**: Python runtime updated from 0.29.0 (Python 3.13) to 314.0.5 (Python 3.14.2).

- **Linked window numbers**: Closed linked windows free their slot. Opening another extra window after closing Linked 1 is Linked 1 again, not Linked 2. Live claims live in `linkedWindowOccupancy.${sessionId}` (heartbeat + stale timeout); this is not part of `windowUi.*`.

Factory chrome is `APP_SETTINGS.DEFAULT_WINDOW_UI_STRING` (`docs` closed, Font Info collapsed, Overview 33%, Editor 67%, bottom row collapsed); missing `windowUi.${slot}` keys for main and linked windows write and apply that string. Layout is persisted on resize (and preference changes), not on window blur/unload. Scroll Overview to Active Glyph defaults on (`follow` omitted; `follow=0` when off). Focus defaults to Editing View (`focus` omitted; other views store `focus=`). Top-row restore width-collapses only panes stored at 0% (24px tabs). All-zero `top=` falls back to that factory editor split. Bottom panes never width-collapse; zero shares there restore equal columns. The top/bottom splitter uses the same 0–1 flex grow as live dragging.
- **Shareable URLs**: Query values keep readable characters (`:`, `/`, `,`, Unicode). Space becomes `+` (`text=hello+world`); a literal plus is `%2B`. Only controls, `#`, `&`, `%`, and `+` are percent-encoded. `text` is no longer double-encoded.

File → New stays an empty font. `?test=` sessions still start empty so Playwright opens are not racing that compile.
- **App updates**: Cached clients can get a new cut again. This service worker activates on install (`skipWaiting`) and tells uncontrolled windows, so a stuck Preferences detector is not required. Checks compare the running `EDITOR_VERSION` to the published worker (including webpack-minified `DISPLAY_VERSION`) and GitHub releases, on boot and when the window becomes active (`document.hasFocus()` plus visibility, polled because macOS/PWA `focus` events are unreliable). `isTest()` follows `?test=` only, not `navigator.webdriver`. If Check for updates finds no newer build, Preferences offers Force update: unregister the worker, clear Cache Storage, reload from the network (same build is possible). The same reinstall runs from `?update`.
- **Outline chrome**: Nodes and handles use two-tier zoom sizing. Corner on-curve points are squares, smooth points are larger circles with a center dot, and points on LSB/RSB, a visible guideline, or a master vertical-metric line (baseline, ascender, x-height, …; not overshoots) are diamonds sized to the same area as the square (smooth keep the dot). On-curve nodes and anchors on those lines or in a metric overshoot band get a lighter gray halo sitting strictly outside the chrome stroke at every selection state; thickness is `NODE_ZONE_HALO_SIZE_RATIO` of the object radius (√2 for diamonds), tracks zoom/hover/select, and is not drawn on off-curve handles. Anchors match the same-shape on-curve chrome (square with square nodes, diamond with diamond nodes), except when they share a location with a node (`ANCHOR_SIZE_RATIO`) so the outer ring stays independently pickable; they are squares except on vertical metrics (equal-area diamonds), with a more transparent orange idle fill and a coral outline that fills solid when selected. Off-curve handles are smaller gray-outline circles that fill `CONTROL_POINT_SELECTED` only when selected (black in light theme, white in dark); their outline uses `HANDLE_LINE_SELECTED` and fill `CONTROL_POINT_OWNER_SELECTED_FILL` (same alpha as unselected, gray; inverted in dark) when the related on-curve node is selected. Idle handle lines are fainter (`HANDLE_LINE_OPACITY`); they turn `HANDLE_LINE_SELECTED` when the handle or its on-curve node is selected. Contour segments keep the unselected outline color unless both on-curve ends are selected, then they stroke `OUTLINE_SELECTED`. Hovering a segment paints that stroke halfway from rest to selected; in-segment handles use the same fill mix as hovering an on-curve node. Unselected on-curve nodes and off-curve handles fill with 20% transparent white; selection fills `NODE_NORMAL` (on-curve) or `CONTROL_POINT_SELECTED` (off-curve). Hovering a handle highlights only that handle, its on-curve node, and that vector line (not the path segment or the opposite handle). The nearest 15% of each segment end (`SEGMENT_HOVER_END_ZONE`, Bezier `t` on curves) counts as hovering that on-curve node instead of the segment. Nodes, anchors, and path segments are hit before component fills. Anchors stacked on a node keep a pick ring just outside the node hit (`ANCHOR_COINCIDENT_HIT_EXTRA`). LSB/RSB handles fill 30% white at rest and 30% of their border color when hovered or selected, and their pick radius uses the same minimum and padding as nodes. Cmd/pen drawing still places points next to those handles and guidelines (plain click drags the chrome). Tunable in `OUTLINE_EDITOR` settings.

# v0.2.1

- **Intermediate Layers and Reinterpolation**: Implemented intermediate layer insertion and deletion together with normal layer reinterpolation flows in the editor.
- **Outline Editing**: Implemented basic outline editing as well as adding nodes to curve and line segments with alt+click complete with preview, and deleting nodes. No drawing new paths yet.
- **Sidebearing Arithmetics**: Added metrics-key editing for left and right sidebearings in the editor property panel, including numeric values, glyph references, local `==` overrides, mirrored references, `@height` measurements, and automatic component offsets. Dependent glyph spacing now recomputes in one batch with synchronized canvas, overview, and editing-font refreshes. The object model now exposes Glyphs-style `leftMetricsKey` and `rightMetricsKey` accessors on glyphs and layers, and the user documentation now includes a dedicated guide to sidebearing arithmetics.
- **Undo Manager + Window Collaboration History Routing**: Added structured undo/redo history ownership across font, glyph, and layer scopes, plus linked-window collaboration that preserves the same history-item IDs and undo targeting across windows. History entries now use a path-based metadata model, deriving glyph, layer, object, and property summaries from changed paths instead of storing duplicated fields. The History panel now shows richer item metadata and acts as the explicit undo context, so toolbar and keyboard undo follow the panel’s current font, glyph, or layer view. Python script execution is recorded as one logical history item by diffing normalized before/after font snapshots, while direct layer and glyph edits keep their own scoped undo managers. For font-scoped undo/redo, the bridge replays the exact targeted history item instead of relying on the root Yjs UndoManager capture state, so a single font-level undo does not collapse unrelated layer or glyph edits.
- **Cross-Window Collaboration**: Added linked-window collaboration for shared change history and undo targeting, so edits and undo/redo actions stay aligned across windows while preserving the correct font, glyph, or layer scope.
- **Component Transform Rendering Fixes**: Fixed several inconsistencies in how component transforms are resolved across exact layers, interpolated layers, and glyph overview tiles. Legacy affine component data is now canonically decomposed into babelfont's decomposed transform model instead of using a lossy conversion, so object-model edits and transform round-tripping preserve scale, rotation, skew, and translation correctly. Interpolated component layers in the Rust/WASM pipeline now interpolate decomposed transform parameters directly, including angle-aware rotation interpolation, instead of linearly interpolating affine matrix coefficients, which eliminates skewed component rendering during live interpolation. Glyph overview rendering now uses the same component-aware interpolation path and derives tile centering bounds from the actual recursively transformed shape tree, so overview tiles match editor rendering more closely for transformed and nested components.
